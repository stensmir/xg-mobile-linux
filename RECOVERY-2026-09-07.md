Verified on ROG Ally Z1 Extreme + XG Mobile GC33Z (RTX 4090 Laptop, 16 GB).

## Working state

- SteamOS 3.8.26, kernel `6.18.46-valve1-1-neptune-618-g2e13b4367b17`.
- NVIDIA 575.64.05, including matching `lib32-nvidia-utils`.
- NVIDIA kernel modules compiled after applying `decky-plugin/XG-Mobile/patches/nvidia-575.64.05-linux-6.18.patch`. This patch targets the installed 6.18 kernel API; do not apply it to the older 6.16 installation.
- `xg-mobile-auto.service` starts the dock successfully after reboot.
- Desktop Mode (Plasma Wayland): HDMI monitor works at 3840×2160, 60 Hz; user confirmed visible picture.
- PoE 2 build 25161798 launches through Proton 11.0 and Steam Linux Runtime 4.0. Both the game log and `nvidia-smi` confirm RTX 4090 rendering. Performance tuning remains subject to measurement in gameplay.
- Default login remains Game Mode. No persistent gamescope launch override was installed.

## Findings that prevent repeating previous failures

- Keep Decky Loader disabled until compatibility with the Steam client is independently established. Previous recovery notes attribute SteamUI/React #130 to the loader, not just this plugin. It was disabled and inactive during driver recovery; see the later scoped Decky test below.
- Keep global NVIDIA EGL registration disabled. Previous versions crashed gamescope during EGL enumeration. `/usr/share/glvnd/egl_vendor.d/` currently contains only Mesa. Keep the NVIDIA Vulkan ICD: games can still use it.
- A bare SSH `vulkaninfo` can fail to enumerate NVIDIA in this setup. `DISPLAY=:0` in a live graphical session exposes both AMD and NVIDIA. A process-local `__EGL_VENDOR_LIBRARY_FILENAMES` pointing to NVIDIA's saved JSON also allowed a headless test; that is not authorization to restore global EGL registration.
- Do not force NVIDIA into `modules-load.d`, unload the live GPU, remove its PCI functions while in use, or power-cycle it through sysfs during gameplay. Historical journals confirm PCIe removal timeouts and ACSViol errors.
- The device's `xgm-shutdown` includes the existing unbind-before-remove fix, matching the staged local change. The new release incorporates this existing change and adds failure checks; the additional checks have not been reboot-tested on this device.

## Monitor tests

The primary gamescope session selected AMD `/dev/dri/card0` and eDP-1. NVIDIA is `/dev/dri/card1` for this boot; device numbers are not stable identifiers.

- `modetest -M nvidia-drm -a -s ...` exited without sending a modeset ioctl. Its zero exit status did not establish successful output.
- The legacy modeset test (`-s 132@62:1920x1080-60`, without `-a`) displayed a visible test pattern. Connector and CRTC IDs are boot-specific.
- A separate headless gamescope process initialized NVIDIA successfully.
- A second DRM gamescope alongside the main Steam session failed to acquire the logind seat (`Device or resource busy`) and crashed during exit. Main Steam remained active; this does not prove gamescope cannot drive NVIDIA when it owns the session.
- Switching through the supported `steamosctl switch-to-desktop-mode plasma.desktop` enabled HDMI in KDE. A temporary 120-second return timer was prepared before switching and canceled after the user confirmed the picture.

Return to Game Mode with `steamosctl switch-to-game-mode`. To use the confirmed monitor path, switch to Desktop Mode and launch Steam games there. No SteamOS reinstall or Preview switch is required for this path.

## PoE 2 baseline and loading checks

- User photo: 39 FPS, frame 26 ms, CPU 22 ms, GPU 8 ms, network 12 ms, VRAM 3.6 GB. This frame indicates a CPU-side limit; it is not a sustained combat benchmark.
- The game uses Vulkan with engine multithreading enabled. The borderless swapchain is actually 3840×2160 despite 1920×1080 saved in the config. No graphics settings were changed during these measurements.
- Initial loading screens in `Client.txt`: Clearfell Encampment 48.236 s; Grelwood 40.044 s. Repeated transitions: encampment 16.598 s then 4.078 s; Grelwood 1.967 s then 1.936 s. User confirmed the repeated loads feel fast. This supports a cache warm-up effect but does not isolate shader compilation from asset/OS caching.
- During the repeated-load sample (14:34:32–14:35:32), CPU I/O wait was about 0–0.1%, NVMe busy time at most 33 ms per sample, and CPU temperature 82–85 °C. No sustained disk saturation was observed in this interval; the initial 40–48 s loads were not instrumented.
- NVIDIA reported 16,376 MiB total VRAM and about 3,701 MiB used. The game nevertheless emitted `[TEXTURE] Insufficient VRAM`; the cause remains unproven. Do not infer physical VRAM exhaustion from that warning alone.
- Raw measurements remain on the device: `/home/deck/.xgm/poe2-gpu-baseline.csv` and `/home/deck/.xgm/poe2-loading-sample.jsonl`.
- User reported 25–40 FPS after repeated loads. A temporary native `steamosctl set-performance-profile performance` test raised sampled CPU frequencies to roughly 3.7–4.6 GHz average and temperature to 95–96 °C. User observed 40 FPS / CPU 33 ms, which did not establish an improvement. Restored `balanced` and canceled `xgm-profile-rollback.timer`; no persistent performance override was added. Samples: `/home/deck/.xgm/poe2-performance-profile.jsonl`.
- Saved the current game config as `/home/deck/.xgm/poe2-vulkan-before-dx12-20260907.ini` before a proposed in-game renderer comparison. DirectX 12 has not yet been tested.
